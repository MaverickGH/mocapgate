# Танцы: GVHMR и экспериментальный SAM-Body4D

Статус: подготовлен эксперимент, **качество моделей на танцах ещё не сравнено**.
SAM-Body4D пока не является новым бэкендом Studio и не экспортирует BVH.

## Что проверяется у GVHMR

`tools/experiments/dance_compare.py` сохраняет исходный BVH и вариант с фиксацией
стоп. Вращения таза и всех суставов не фильтруются повторно. Проверяется поворот
корня после округления и записи в BVH, а также минимальная высота стоп.
Синтетический тест включает наклоны таза с частотой 4 Гц, полный поворот и
согнутые колени; он проверяет сохранность экспорта, а не качество распознавания.

Поправка пола теперь не может быть меньше текущего проникновения стопы:
сглаживание сохраняется при отпускании поправки. Это устраняет запаздывание
вертикальной коррекции при полной фиксации. Метод по-прежнему не использует IK
и может сдвигать всё тело; поэтому всегда смотрите оба варианта.
Регулятор «сглаживание» существующего приложения применяется к MediaPipe,
а не к позам GVHMR. Увеличивать его ради качества GVHMR бессмысленно.

## Отдельные окружения

Нужен Linux / NVIDIA CUDA или соответствующая GPU-сессия Colab. На Mac ARM64
этот эксперимент не проверен. Используйте разные Python-окружения для GVHMR
и SAM-Body4D; не устанавливайте их зависимости в bundled Python Studio.

Для GVHMR используйте существующую настройку MoCapGate и
[инструкцию проекта](https://github.com/zju3dv/GVHMR).
Для SAM-Body4D получите отдельный checkout **за пределами MoCapGate**:

```bash
git clone https://github.com/gaomingqi/sam-body4d /absolute/path/sam-body4d
git -C /absolute/path/sam-body4d checkout 21af1020979ef32ddf6be3597ef59a68bad2f1bf
```

Установите окружение по [upstream README](https://github.com/gaomingqi/sam-body4d/tree/21af1020979ef32ddf6be3597ef59a68bad2f1bf),
включая PyTorch/CUDA, Detectron2, SAM3 и зависимости проекта. Отдельно получите
доступ к SAM3 и SAM 3D Body на Hugging Face и примите условия их моделей.
Запустите upstream `scripts/setup.py --ckpt-root /absolute/path/checkpoints`.
Проверьте `configs/body4d.yaml`: пути должны указывать на полученные веса;
используйте абсолютный `paths.ckpt_root`. Worker создаёт свою конфигурацию и
не перезаписывает исходную. Веса не входят в MoCapGate или Git.

По умолчанию эксперимент отключает diffusion completion и использует batch=4.
Это сокращает расход ресурсов, но совместимость с конкретной видеокартой
нужно подтвердить запуском. В [профиле upstream](https://github.com/gaomingqi/sam-body4d/blob/21af1020979ef32ddf6be3597ef59a68bad2f1bf/assets/doc/resources.md)
один человек / 100 кадров / batch=64 без completion использовали пик 14.49 GB
на H800. Это не измерение нашего batch=4 и не гарантия запуска на T4.

## Один клип для двух моделей

Начните с одного человека и 10–15 секунд. Тело целиком в кадре; неподвижная
камера, хороший свет. Для сложных ракурсов подготовьте отдельные эксперименты.
Все пути в примерах замените на свои. Папка эксперимента должна быть новой
и находиться за пределами публичного репозитория.

```bash
python tools/experiments/dance_compare.py prepare /absolute/path/dance.mp4 /absolute/path/experiment
python tools/experiments/dance_compare.py gvhmr /absolute/path/experiment --python /absolute/path/gvhmr-env/bin/python --repository /absolute/path/GVHMR --static
python tools/experiments/dance_compare.py sam /absolute/path/experiment --python /absolute/path/body4d-env/bin/python --repository /absolute/path/sam-body4d
python tools/experiments/dance_compare.py report /absolute/path/experiment
```

Уберите `--static`, если камера движется. GVHMR использует подготовленный
30 fps клип. SAM получает извлечённые из того же клипа кадры; это обходит
upstream поиск человека с десятого кадра, который ломает короткие видео.
Извлечение JPEG добавляет небольшой фактор сжатия; это не побитовое сравнение
входных пикселей. SHA-256, FPS, размер изображения и число кадров проверяются.
Больше 1800 кадров не допускается из-за предела upstream tracking.

На повторный запуск создавайте новую папку: результаты не перезаписываются.
При ошибке SAM сохраняется частичный JSON с `completed=false`; отчёт такой
результат не принимает. Не заполняем пропуски выдуманными позами.

## Просмотр и выводы

Откройте `comparison.html` рядом с `input-30fps.mp4`. Если браузер не воспроизводит
локальное видео, запустите из папки эксперимента:

```bash
python -m http.server 8765 --bind 127.0.0.1
```

Затем откройте `http://127.0.0.1:8765/comparison.html`.
Наложения можно включать отдельно: голубой GVHMR, оранжевый SAM. Самостоятельные
рендеры upstream SAM могут иметь другой FPS; для сравнения используйте этот отчёт.

Смотрите наклон таза, сохранение ритма, глубокие приседания, повороты и стопы.
В Blender сравните `gvhmr-raw.bvh` и `gvhmr-foot-lock.bvh` на одном персонаже.
`metrics.json` содержит проверку экспорта и отсутствующие кадры SAM.

MHR keypoints и суставы SMPL имеют разные определения. Наложение GVHMR
использует приблизительные нейтральные длины костей и первую матрицу камеры.
Камерная траектория SAM не равна мировой траектории GVHMR. Без эталонного
захвата нельзя объявить победителя по «меньшему дрожанию»: сглаженная модель
может просто потерять движение. Счёт точности и автоматический рейтинг
поэтому не рассчитываются.

Для полноценного BVH из SAM нужен проверенный перевод MHR в скелет/позы,
включая локальные системы костей, rest-позу и root motion. Сохранённые raw MHR
параметры позволяют вернуться к этому после реального теста; они не выдаются
за готовые SMPL-параметры.

## Проверка и распространение

```bash
python -m unittest discover -s tests -p 'test_dance_compare.py'
python -m unittest discover -s tests -p 'test_retarget.py'
python -m unittest discover -s tests -p 'test_smpl_bvh.py'
```

Изменён `core/cleanup.py`, один из native-модулей. Уже собранный Studio не
получит эту правку автоматически. Перед новым выпуском нужно отдельно
пересобрать native-пакет на CPython 3.12.13 и проверить распакованный пакет.
Эксперимент не устанавливает модели, не публикует результаты и не меняет
публичный origin. Текущий код MoCapGate — Apache-2.0, Copyright CYBER Department.
GVHMR/SMPL-X и SAM-модели сохраняют собственные условия.

## Фактическая проверка на Mac (7 октября 2026)

Checkout закреплённого SAM-Body4D проверен отдельно от Studio. Запуск worker
с настоящим тестовым видео остановился на диагностике отсутствия CUDA:
`This experiment requires NVIDIA CUDA; MPS/CPU is unverified`. Это проверка
ошибки окружения, а не успешное распознавание. Веса SAM-Body4D не скачивались
и результат качества не заявляется.

Подготовка видео 25 FPS дала 30 кадров при 30 FPS и длительность 1 секунду;
сохранены исходный и подготовленный SHA-256 и временные метки. Четыре теста
эксперимента проверяют сохранение вращений при коррекции стоп, raw-параметры,
совпадение видео/таймлайна и отклонение незавершённых результатов.

SAM 3D Body, используемый внутри GEM-X для признаков, и SAM-Body4D — разные
конвейеры. Успешный тест GEM-X на Mac не доказывает работу SAM-Body4D.
Следующий этап — короткий GPU-запуск с completion выключенным и batch=1,
затем сравнение с GVHMR на том же ролике. Увеличивать batch и длительность
нужно после измерения памяти; соответствие модели видеокарте заранее не
гарантируется.
