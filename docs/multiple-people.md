# Несколько людей

[English](multiple-people.en.md)

**Текущий статус:** групповой режим экспериментальный. Проверка двух людей и их ID на настоящем видео
Sports2D пройдена; это не проверка точности всех суставов в 3D: [результат проверки](multiple-people-real-test.md).

GEM-X и GVHMR обрабатывают несколько людей на общем таймлайне.
В настройках дубля «Максимум людей» задаётся от 1 до 8, по умолчанию 4.
Это предел обнаружения одновременно присутствующих людей, а не обещание точности
для восьми человек в тесной толпе. При нескольких людях по умолчанию выбраны
«Все участники»: все видимые скелеты показаны одновременно в 2D и 3D.
«Участник ID 2» означает второго участника, а не число людей для обнаружения.
Для отдельного отчёта, скачивания и открытия в Blender/Maya выберите нужный ID.
Кнопка создания FBX экспортирует всех участников; экспорт для движков может собрать
всех в один файл («Все участники одним файлом»).

Если людей несколько, файлы называются `<имя>_person_<ID>.bvh`, `.ma` и `.fbx`.
У одного человека сохраняется прежнее имя файла. Все файлы имеют общие FPS и длину;
за пределами наблюдаемого интервала поза удерживается, а просмотр скрывает участника.
Короткие пропуски интерполируются. Старые одиночные дубли продолжают открываться.

## GEM-X

С 0.3.3 beta. Один проход **YOLOX + ByteTrack** по всему видео находит людей и связывает их
в треки. Участником считается устойчивый трек не короче **0,25 с** (настраивается); треки
сортируются по суммарной площади рамки, берутся первые «Максимум людей». Для каждого
участника отдельно вычисляются 2D-точки, признаки SAM 3D Body и движение GEM-X.

- **Своя анимация у каждого:** BVH, сцена Maya и, при выбранном риге Man_Rig, свой Man_Rig
  на каждого участника; при включённой мимике — свои 52 кривые.
- **Общая сцена:** положение каждого берётся относительно камеры, вертикаль — по гравитации;
  все стоят на общем полу **Y = 0** (по стопам). У дубля показана высота камеры над полом.
- **Настройки дубля:** «Уверенность обнаружения людей» (ниже — находит мелких и частично
  закрытых, но больше ложных), «Минимальная длительность участника, с» (короче — не участник:
  прохожие, мелькание у края), «Помнить потерянного человека, кадров» (сколько кадров человек
  может быть закрыт и сохранить ID; 30 ≈ 1 с).

Взаимное расположение и контакты между людьми приблизительные. Многолюдный режим GEM-X
проверен меньше, чем одиночный: начните с одного человека ([что проверено](verification.md)).

## GVHMR

Локальный GVHMR использует отдельные траектории YOLO и последовательно обрабатывает
их одним GPU. Каждая мировая траектория оценивается независимо; точные взаимные
позиции и взаимодействия людей не гарантируются. Colab экспортирует сцену `mocapgate.scene/1` и отдельные BVH
в одном ZIP. Импорт ZIP/JSON сохраняет все ID. Для полного запуска нужен лицензируемый
`SMPLX_NEUTRAL.npz`; в Windows проверена предобработка двух людей на GTX 1080; короткие ID меньше 0,25 секунды отбрасываются,
а полный запуск со статичной камерой после подключения пользовательской модели
проверен на этом же видео: два участника, BVH/FBX и 230 кадров.
Это не проверка точности 3D всех суставов; подробности — в отчёте реального теста.

## MediaPipe (прежний путь)

MediaPipe больше не предлагается как модель тела в Studio; путь остался в CLI (`--backend mediapipe`)
и для старых дублей. В нём люди обнаруживаются отдельным EfficientDet Lite2 (~24 МБ) по полному кадру
и перекрывающимся плиткам, поза распознаётся внутри каждого бокса, привязка к ID использует
положение, размер и сглаженную скорость. Положение участников в 3D приближённое.

## Общие ограничения

После долгого отсутствия человек получает новый ID. При полном перекрытии и похожих позах ID могут
перепутаться; автоматического восстановления личности по внешности нет. Для групп оставляйте
расстояние между людьми и снимайте всё тело. С одной камеры нельзя гарантировать точную глубину
или контакты между людьми.

## Командная строка

```powershell
python mocapgate.py new duet.mp4 --backend gemx-local --max-people 4
python mocapgate.py new duet.mp4 --backend gvhmr-local --max-people 2
python mocapgate.py process <папка-дубля> --fbx
```

Прямой импорт сцены GVHMR также создаёт BVH для каждого участника:

```powershell
python mocapgate.py scene.mocapgate.json -o duet.bvh
```

Короткий режим `mocapgate.py video.mp4 -o out.bvh` относится к прежнему пути MediaPipe и копирует только
основной BVH. Для явного управления группой и доступа к каждому результату используйте Studio или команду `new`.

## GVHMR: несколько людей в одной сцене (0.3.3 beta)

У GVHMR траектория каждого человека начинается из нуля со своим поворотом — раньше в 3D все стояли в одной точке.
Теперь участники переводятся в мир первого через общую неподвижную камеру (как у GEM-X): места и направления
как на видео, пол общий (Y = 0). Участники без данных камеры остаются как есть (в журнале — «без данных камеры»).
При «Перемещение: на месте» перевод не делается.
