# Несколько людей

**Текущий статус:** исправлены дубликаты и смена ID на настоящем тесте Sports2D.
Проверка двух людей и их ID пройдена; это не проверка точности всех суставов в 3D:
[результат проверки](multiple-people-real-test.md).

MediaPipe и адаптер GVHMR обрабатывают несколько людей на общем таймлайне.
В настройках дубля «Максимум людей» задаётся от 1 до 8, по умолчанию 4.
Это предел обнаружения одновременно присутствующих людей, а не обещание точности
для восьми человек в тесной толпе. При нескольких людях по умолчанию выбраны
«Все участники»: все видимые скелеты показаны одновременно одинаковыми цветами в 2D и 3D.
«Участник ID 2» означает второго участника, а не число людей для обнаружения.
Для отдельного отчёта, скачивания и открытия в Blender/Maya выберите нужный ID.
Кнопка создания FBX экспортирует всех участников.

Если людей несколько, файлы называются `<имя>_person_<ID>.bvh` и `.fbx`.
У одного человека сохраняется прежнее имя файла. Все файлы имеют общие FPS и длину;
за пределами наблюдаемого интервала поза удерживается, а просмотр скрывает участника.
Короткие пропуски интерполируются. Старые одиночные дубли продолжают открываться.

Для видео MediaPipe сначала обнаруживает людей отдельным EfficientDet Lite2 (~24 МБ,
скачивается автоматически при первой групповой обработке). Полный кадр и перекрывающиеся
плитки помогают находить небольших людей. Повторные боксы подавляются, поза распознаётся
отдельно внутри каждого бокса. Привязка использует положение, размер и сглаженную скорость.
Одиночный режим сохраняет видео-трекинг MediaPipe. Живое превью камеры остаётся предварительным;
сохранённая запись проходит новый конвейер обработки видео. После долгого
отсутствия человек получает новый ID. При полном перекрытии и похожих позах ID могут
перепутаться; автоматического восстановления личности по внешности здесь нет.
Для групп оставляйте расстояние между людьми и снимайте всё тело. Положение
участников MediaPipe в 3D приближённое: используется общая оценка фокуса камеры.
С одной камеры нельзя гарантировать точную глубину или контакты между людьми.

Локальный GVHMR использует отдельные траектории YOLO и последовательно обрабатывает
их одним GPU. Каждая мировая траектория оценивается независимо; точные взаимные
позиции и взаимодействия людей не гарантируются. Обновлённый Colab экспортирует сцену `mocapgate.scene/1` и отдельные BVH
в одном ZIP. Импорт ZIP/JSON сохраняет все ID. Для полного запуска нужен лицензируемый
`SMPLX_NEUTRAL.npz`; в Windows проверена предобработка двух людей на GTX 1080; короткие ID меньше 0,25 секунды отбрасываются,
а полный запуск со статичной камерой после подключения пользовательской модели
проверен на этом же видео: два участника, BVH/FBX и 230 кадров.
Это не проверка точности 3D всех суставов; подробности — в отчёте реального теста.

CLI для видео с несколькими людьми:

```powershell
python mocapgate.py new duet.mp4 --backend mediapipe --max-people 4
python mocapgate.py process <папка-дубля> --fbx
```

Прямой импорт сцены GVHMR также создаёт BVH для каждого участника:

```powershell
python mocapgate.py scene.mocapgate.json -o duet.bvh
```

Короткий режим `mocapgate.py video.mp4 -o out.bvh` копирует только основной BVH
из созданного дубля; предел людей берётся из настроек. Для явного управления
группой и доступа к каждому результату используйте Studio или команду `new`.
