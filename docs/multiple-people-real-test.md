# Проверка на настоящем видео — 3 октября 2026

Источник: [Sports2D / Demo / demo.mp4](https://github.com/davidpagnon/Sports2D/blob/main/Sports2D/Demo/demo.mp4).
Мужчина прыгает с возвышения, женщина проходит через кадр. Это разные люди в
одной настоящей съёмке, без зеркальных копий или монтажа двух одинаковых фигур.
SHA-256 скачанного исходника: `D9A66417185647B112304B57093F0C180F37A768E6A14DACA75CA541F3B78039`.
Для совместимого просмотра видео перекодировано в H.264 без изменения размера.
Обработаны 230 кадров при 30 FPS, разрешение 1768×994.

## Исправленная обработка MediaPipe heavy: проверка ID пройдена

EfficientDet Lite2 на полном кадре и квадратных плитках выделяет отдельные боксы людей.
После подавления повторных боксов MediaPipe heavy распознаёт одну позу в каждом расширенном
на 25% боксе. Сглаженная ограниченная скорость боксов не допускает скачка прогнозируемого
положения при изменении высоты бокса во время перекрытия деревом.

Полная повторная обработка с пределом 4 дала **ровно два ID**: мужчина 1 (207 наблюдений),
женщина 2 (163 наблюдения); общий таймлайн 230 кадров, 30 FPS. Все 12 ручных проверок
на восьми кадрах пройдены, включая ID мужчины после приземления. Отчёт сохранён
в `tests/fixtures/sports2d/corrected.json`, новые детекции — в `crop_detections.json.gz`.
Старый ошибочный результат сохранён как исторический пример; тест проверки корректно его отвергает.

Ещё один полный запуск через интерфейс с пределом **2** также прошёл все контрольные
кадры, с теми же ID 1 и 2. В установленную Windows-сборку добавлен дубль
«Sports2D — исправлено, два человека». Старый тест помечен как ошибочный (9 ID).

Studio показывает обоих участников одновременно, скрывает скелет на кадрах без наблюдения,
сохраняет время видео при переключении ID. Для каждого создаются независимые BVH/FBX
по 230 кадров. Исправлены маршруты дублей и файлов с русскими названиями.
Оценка обнаружения и пропусков участника ограничена его интервалом присутствия;
до входа и после выхода из кадра полоса качества серая.

55 автоматических тестов прошли на Windows, без пропусков и ожидаемых ошибок.
NSIS установлен поверх предыдущей версии; проверены ресурсы установленной копии,
MSI после административного извлечения и переносного ZIP. Обычная установка MSI
отдельно не выполнялась. Для обоих FBX проверен обратный импорт в Blender 4.5.14:
22 кости, 230 кадров, 30 FPS, максимальная разница матриц с BVH < 0,001.

**Точность движения ещё ограничена.** Для этого клипа оценки 32/100 и 30/100:
видны дрожание, скольжение стоп и неоднозначная глубина. Проверка количества и ID
не означает высокую точность 3D-позы. Обработка с отдельными детекциями заметно медленнее
одиночного видео-трекинга на CPU. Плотная толпа и полное перекрытие похожих людей не проверены.

## Первоначальная обработка MediaPipe heavy: проверка не пройдена

Команда: `mocapgate.py new real-people-test.mp4 --backend mediapipe --max-people 4`.
Поза найдена хотя бы для одного человека в 228/230 кадрах, однако создано девять
ID вместо двух: 1, 2, 3, 4, 5, 6, 7, 9, 10. Раздельные BVH технически создаются,
но это фрагменты и ошибочные копии, а не девять настоящих участников.

На кадре 21 MediaPipe возвращает две позы мужчины; на кадре 73 — две позы женщины;
на кадре 106 — три позы женщины. Некоторые копии имеют сильно искажённые бёдра,
поэтому привязка по положению и форме создаёт новые ID. При прыжке и приземлении
ID мужчины также меняется. Короткие синтетические проверки не выявили этот случай.

Простые варианты подавления похожих поз и расширения допуска движения были
проверены на сохранённых точках, но не дали двух устойчивых траекторий. Эти
экспериментальные изменения не включались в приложение. Для надёжного группового
MediaPipe требуется отдельное обнаружение людей, подавление повторных боксов,
распознавание позы внутри каждого бокса и проверка непрерывности ID на реальных клипах.

## GVHMR: полный локальный запуск на Windows

YOLO выделил две длинные траектории (ID 1: кадры 0–227; ID 2: 37–200) и дополнительную
короткую (ID 4: 205–210). Поэтому один только результат «обнаружены несколько ID»
не подтверждает правильное количество участников. ViTPose и HMR2 обработали
две основные траектории на GTX 1080. После установки скачанной пользователем
официальной SMPL-X v1.1 полный расчёт движения завершился для обоих участников.
Дополнительная траектория расположена у левого края кадра (центр бокса X ≈ 48 пикселей),
где женщина заканчивает проход. Это соответствует разрыву её ID при выходе из кадра,
а не отдельному полному участнику. Предобработка этой короткой траектории тоже завершилась.

Повторная проверка после добавления минимального подтверждения ID в 0,25 секунды
оставила ровно две основные траектории: 1 (0–227) и 2 (37–200). Короткий ложный ID 4
больше не экспортируется.

Полный запуск `core/gvhmr_runner.py --static --max-people 2` завершился на GTX 1080
(8 ГБ VRAM): два участника, общий таймлайн 230 кадров, 30 FPS. Все значения
параметров тела и траекторий конечны. Проекция таза в системе камеры попала в
ручные контрольные области во всех 12 проверках; ID мужчины и женщины сохраняются.
Это проверка привязки и количества, а не эталонная оценка точности 3D.

Для каждого участника созданы BVH и FBX с точными длинами костей из SMPL-X.
Обратный импорт FBX в Blender 4.5.14 подтвердил 22 кости и 230 кадров;
максимальное отклонение матриц от BVH — 0,0000613 (< 0,001).
Встроенные оценки качества — 70/100 и 56/100 (MediaPipe на этом клипе: 32/100 и 30/100).
Эти эвристические оценки не заменяют сравнение с эталонным захватом движения.
Дубль «Sports2D — GVHMR, два человека» добавлен в библиотеку установленного приложения.

В Python 3.12 приложения добавлен NumPy в пользовательскую папку пакетов;
после установки требуется перезапуск приложения, если папка не существовала при старте.
Лицензионная модель SMPL-X хранится только в локальной установке GVHMR, вне репозитория.
Рендерер PyTorch3D и режим движущейся камеры в этой проверке не использовались;
полный расчёт и экспорт выполнены без рендера, со статичной камерой.

Исходное видео, точки, BVH, контактный лист и машинный отчёт находятся в игнорируемом
`dist`. Актуальный результат MediaPipe приведён выше.

Видео H.264, источник, лицензия, контрольные кадры и сохранённые детекции теперь
включены в [постоянный тестовый пример](../tests/fixtures/sports2d/README.md).
Повторная проверка: `python tools/check_multi_person_video.py`. Она проверяет два
участника и сохранение ID, возвращая ненулевой код при ошибке. Обычные тесты
содержат проверку целостности и проходящую регрессию исправленных детекций без `expectedFailure`.
Исторический повторный запуск старого конвейера воспроизвёл те же девять ID. Его отчёт сохранён как
`tests/fixtures/sports2d/baseline.json`; критерий проверки остаётся **два человека**.


## Опциональные кисти и лицо

Опции «Пальцы рук (BVH / FBX)» и «Полное лицо и мимика (JSON)» добавлены
для MediaPipe и локальных/импортированных результатов GVHMR с видео.
По умолчанию выключены. Обработка выполняется после захвата тела, на общей
временной шкале, с привязкой к запястьям и голове каждого ID.
Неоднозначные близкие запястья отбрасываются, а не назначаются другому участнику.

Проверка Sports2D, 230 кадров: ID 1 — левая кисть 50, правая 108, лицо 78 кадров;
ID 2 — левая 148, правая 98, лицо 9 кадров. Это покрытие детекций, а не оценка
точности пальцев: мелкие кисти, поворот лица, размытие и перекрытия дают пропуски.
Отдельные положительные проверки на официальных тестовых изображениях MediaPipe
`thumb_up.jpg` и `portrait.jpg` подтвердили 21 точку кисти, 478 точек лица и 52
коэффициента мимики. Изображения и результаты этих запусков остаются в `dist`.

BVH/FBX содержит 22 кости тела и 30 костей пальцев (по три на каждый палец).
Пальцы используют приближённые взрослые длины костей; вращение запястья остаётся
от модели тела, движения фаланг вычисляются относительно ладони.
Пропуски до 0,15 секунды удерживают последнюю позу, длинные возвращают нейтральную;
в исходном JSON пропуски всегда остаются `null`. Оценка качества тела не оценивает пальцы.
Обратный импорт обоих FBX в Blender подтвердил 52 кости, 230 кадров и разницу
матриц < 0,001 (максимум 0,000147).

Файл `capture_person_<ID>.json` содержит точки кистей в изображении и метрах,
полное лицо с относительной глубиной изображения, 52 именованных коэффициента
мимики и матрицу лица относительно вырезанного участка. Он доступен для скачивания
после выбора ID. Мимика не записывается в скелетный BVH/FBX: нужен совместимый лицевой
риг с blendshape-каналами. Приложение рисует найденные детали поверх видео;
после записи камеры они вычисляются при обработке, а не в живом предпросмотре.

Пятка и носок доступны в существующих 33 точках MediaPipe Pose. Независимое
распознавание каждого пальца ноги не поддерживается и не имитируется.
3D-просмотр теперь кадрируется по всем суставам видимых участников в текущем кадре, включая поднятые
платформы и пальцы, вместо фиксированной точки около пола.

## Полная поверхность SMPL-X на Windows

Опция `body_surface` использует установленную лицензированную модель, окружение
torch/smplx и текущие движения GVHMR либо MediaPipe. Для каждого ID создаются
10 475 вершин, 20 908 треугольников и 55 суставов. Кисти используют rest-позу
этой же модели и наблюдаемую ориентацию ладони; кости пальцев в просмотре тоньше
костей тела. Челюсть и глаза также используют небольшие маркеры.
Режимы просмотра: тело, кости, прозрачное тело с костями.

Sports2D: два участника, 230 кадров, все координаты конечны. На контрольных
кадрах 0, 58, 122, 180 и 229 максимальная разница FK экспортированного BVH
и суставов поверхности — 0,000239 м для ID 1 и 0,000209 м для ID 2.
Вершины хранятся относительно таза с шагом 0,1 мм (либо float32 для больших
моделей); модель SMPL-X в установщик и Git не включается.

Мимика — приближённая регуляризованная подгонка 100 коэффициентов выражения,
челюсти и головы к 51 внутренней точке лица. Соответствия с MediaPipe выбраны
вручную; это не восстановление внешности и не гарантия точной мимики.
Положительная проверка на трёх кадрах официального тестового портрета MediaPipe:
нормированная ошибка точек снизилась с 0,03796 до 0,00390. Это статический
портрет, а не проверка динамической мимики. На Sports2D лицо найдено лишь
на 78 и 9 кадрах соответственно; исходные пропуски сохраняются.
BVH/FBX экспортирует 55 суставов, без поверхности и лицевых blendshape-каналов;
52 именованных коэффициента MediaPipe сохраняются в отдельном JSON.

Проверки ядра на Windows: 63 теста прошли, включая независимое сравнение FK
всех 55 суставов и проверку перехода координат камеры в Y-up.
Обратный импорт обоих полных FBX: 55 костей, 230 кадров, максимальная разница
матриц 0,000184. MediaPipe также прошёл полный расчёт поверхности для двух
людей на 230 кадрах; кисти/лицо: ID 1 — 48/115/75, ID 2 — 155/8/14.
NSIS/MSI собраны, NSIS установлен с кодом 0; проверка упакованного приложения
подтвердила работу CLI и локального сервера. В браузерном просмотре проверены
обычная и прозрачная поверхности двух ID; ошибок JavaScript не обнаружено.
