# Экспорт для игровых движков

[English](engines.en.md) · [README](../README.md) · [Проверено / не проверено](verification.md)

Откройте обработанный дубль → «Экспорт» → **«Для игровых движков»**. Для FBX и GLB нужен Blender
(ставится в «Модели и инструменты» → «Установить всё рекомендуемое»). Файлы сохраняются в папке дубля
и скачиваются кнопками, которые появляются после экспорта.

| Кнопка | Файл | Что внутри |
|---|---|---|
| **Unreal · FBX** | `<дубль>.unreal.fbx` | Кости переименованы по образцу UE5 Mannequin (`pelvis`, `spine_01`, `thigh_l`, `hand_r`, `thumb_01_l`…), кость `root` в начале координат над `pelvis`. Сантиметры, Y вверх / −Z вперёд, без leaf-костей |
| **Unity · FBX** | `<дубль>.unity.fbx` | Имена в стиле Mixamo без префикса `mixamorig:` — для автосопоставления Humanoid; масштаб запечён в трансформы |
| **glTF · GLB** | `<дубль>.glb` | Метры, Y вверх, скелетная анимация и анимация morph-весов (мимика) |
| **Live Link Face · CSV** | `<дубль>.livelink.csv` | Только мимика выбранного участника; кнопка видна, если в дубле есть кривые мимики |

## Опции

- **«Root motion (перемещение несёт отдельная корневая кость)»** — горизонтальное перемещение и поворот
  по вертикали (yaw) переносятся с таза на корневую кость; таз сохраняет высоту, наклоны и остаток движения.
  В Unreal-экспорте кость `root` есть всегда, в Unity с этой опцией добавляется кость `Root` над `Hips`.
- **«Все участники одним файлом»** — видна, если в дубле больше одного человека. Каждый участник — отдельная
  арматура; взаимное расположение берётся из BVH. Файл получает суффикс `_all`.
- **Мимика.** Если у участника есть кривые лица ([подробнее](facial-expressions.ru.md)), FBX и GLB получают
  служебный меш `FaceExpressions` у кости головы с 52 blend shapes с именами ARKit и их анимацией.

## Ещё форматы, камера и звук

- **Mixamo · FBX** — имена `mixamorig:`, сантиметры, объект «Armature», как у загрузок Mixamo.
- **Cascadeur · FBX** — имена Mixamo без префикса, сантиметры.
- **Blender · .blend** — готовая сцена Blender: скелеты, действия по участникам, мимика, камера съёмки и звук на таймлайне.
- **Камера съёмки** (матчмув) попадает в FBX, GLB и .blend, если она посчитана: для GEM-X — общая камера сцены,
  для GVHMR — по первому участнику. Камера неподвижная (одна усреднённая поза), искажения объектива не учитываются.
  Файл `camera.json` (`mocapgate.camera/1`) лежит в дубле; в 3D есть вид «Из камеры съёмки», в сцене Maya — `CaptureCamera`.
  При «Перемещение: на месте» камера не пишется — она не совпала бы с анимацией.
- **Звук** видео сохраняется как `audio.wav`: узел `MoCapGateAudio` в сценах Maya (с кадра 1), звуковая дорожка в .blend
  и в «Открыть в Blender», кнопка «Звук из видео (WAV)». Во фрагменте — `capture.wav`, обрезанный по участку и
  ускоренный/замедленный вместе со «Скорость ×» (в бесшовном цикле звук не кладётся).

## Ограничения скелета Unreal

Имена соответствуют UE5 Mannequin частично: у MoCapGate три позвонка, поэтому экспортируются `spine_01`,
`spine_03`, `spine_05`; `spine_02` и `spine_04` отсутствуют. Twist-кости (`upperarm_twist_01_l`…) есть только
там, где они есть в исходном скелете (GEM-X/SOMA). Если анимация нужна на Manny или другом персонаже, перенесите
её через IK Retargeter: цепочки сопоставляются по начальной и конечной кости.

## Live Link Face CSV

Раскладка столбцов повторяет записи приложения Live Link Face (Timecode, BlendShapeCount, 52 кривые ARKit,
затем 9 столбцов поворотов головы и глаз). Это не спецификация Epic: формат воспроизведён по записям приложения.
Повороты головы и глаз не захватываются и записываются нулями. Timecode имеет вид `ЧЧ:ММ:СС:КК.ммм`, начинается с нуля, без drop-frame.

## Что проверено

Экспорт проверен повторным импортом в Blender 3.5, 4.2 и 5.2 (кости, кадры, blend shapes). **Импорт в Unreal Engine и Unity, а также Live Link Face CSV в Unreal/MetaHuman
не проверены.** Проверьте масштаб, root motion и сопоставление скелета в своём проекте.
