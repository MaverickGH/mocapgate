# Восстановление установки GVHMR

Windows: если WSL сообщает `WSL_E_WSL_OPTIONAL_COMPONENT_REQUIRED` / `0x80040321`, проверьте состояние компонентов «Подсистема Windows для Linux» и «Платформа виртуальной машины». Если после перезагрузки Windows откатывает включение, журнал установки показывает доступную диагностику компонентов, недавние ошибки Setup/Application и строки CBS.log. Чтение состояния компонентов может требовать запуска PowerShell от администратора. Приложение не удаляет сетевые адаптеры и не меняет службы Windows.

Ошибки `0x800706be`, `0x800f0922`, `NetSetupAI.dll`, `NetSetupEngine.dll` или `vms_pp` требуют диагностики обслуживания и сетевых компонентов Windows. Большое количество старых TAP-адаптеров может заслуживать проверки специалистом; связь с откатом не установлена. Сетевые адаптеры нельзя удалять без понимания их назначения и согласия владельца.

Дистрибутив в состоянии `Installing` не считается готовым. Завершите первый запуск или выберите другой готовый дистрибутив в настройках WSL. Автоматический выбор пропускает `Installing`; данные и незавершённые дистрибутивы сохраняются. Приложение не выполняет `wsl --unregister`.

Для сборки зависимостей устанавливается `python3-dev` вместе с компилятором, venv и Tk. После лимита Google Drive установщик использует резервный `camenduru/GVHMR`, закреплённый commit. Каждый из четырёх файлов проверяется по размеру и SHA-256 до замены рабочего файла. SMPL-X с зеркала не скачивается: пользователь получает её у авторов.

По пользовательскому отчёту проверен запуск GVHMR в WSL2: CUDA-операции, 60 кадров тестового видео, два человека, результат JSON с конечными числовыми значениями, статичная камера. Это проверка на отдельном компьютере; обработка пользовательского видео через Studio в этом отчёте ещё не проверена.
