# MoCapGate Studio 0.3.3-beta.6 — подготовка релиза

Основа — beta.5 (MetaHuman-инструменты, модели в комплекте, GPU-окружение GEM-X) плюс:

- **GEM-X для нескольких людей.** Один проход YOLOX+ByteTrack, до «Сколько людей» устойчивых треков
  (не короче 0,25 с), для каждого свои 2D-точки, признаки SAM-3D-Body и GEM-X. На каждого участника —
  BVH и сцена Maya, переключатель участников в дубле. Результат `mocapgate.soma/2`; старый `soma/1` читается.
- **GEM-X: место и высота относительно камеры.** Положение берётся из параметров GEM-X в системе
  камеры; плавная мировая траектория сдвигается к нему (медиана), вертикаль — по гравитации.
  Участники в одной сцене, пол Y=0 по стопам, высота камеры над полом показана у дубля.
- **GEM-X: наложение скелета на видео и проверка качества** — как у GVHMR, по каждому участнику.
- **Удаление дубля насовсем**: папка дубля целиком, очередь, копии в `.trash`; идущая обработка
  отменяется. Кнопка «Удалить старую корзину».
- **Ошибки**: «No module named 'numpy'» во встроенном Python (SMPL-X для MediaPipe-поверхности и
  кистей/лица) — кости считаются в окружении модели. Сообщения о сбое моделей: причина первой строкой,
  нехватка памяти WSL распознаётся, лог без строк прогресса и ANSI-кодов.
- **Ход обработки**: список шагов (пройденные, текущий с %), «Шаг N · прошло · осталось ~».
- **Настройки GEM-X** (раньше были скрыты все, кроме FPS и стабилизации кистей): сколько людей, режим модели
  (быстро ONNX / точно PyTorch + постобработка контактов стоп / максимум DDIM 50 шагов), фокус камеры,
  уверенность детектора людей, минимальная длительность участника, память трекера, перемещение
  (как на видео / на месте), префикс Mixamo (раньше игнорировался). Кэш распознавания — на набор настроек.
- **Мимика лица в анимацию.** Раньше 52 коэффициента выражений (ARKit) оставались только в capture-JSON.
  Теперь на каждого участника: `<дубль>.face.csv` (кадр, время, 52 кривые на FPS экспорта; пропуски
  заполняются между соседними кадрами) и узел `FaceExpressions` с ключами в сцене Maya — атрибуты с
  именами ARKit подключаются к blendShape персонажа. Кнопки «Мимика (52 кривые, CSV)» и «Кисти / лицо (JSON)»
  в окне приложения сохраняют файлы в «Загрузки».
- **GEM-X: лицо и мимика.** Галочка «Полное лицо и мимика» теперь есть и у GEM-X: MediaPipe ищет лицо по
  кадрам `gemx-input.mp4` (те же 30 FPS), голова каждого участника — из скелета SOMA на кадре. Пальцы,
  глаза и челюсть у GEM-X — в самом скелете SOMA; захват кистей и поверхность SMPL-X — только GVHMR.
- **Мимика в FBX, фрагментах и персонаже**: в FBX — служебный меш `FaceExpressions` у кости головы с 52
  blend shapes ARKit и их анимацией (Unreal / Unity / Maya читают по именам); экспорт фрагмента обрезает
  кривые мимики по тем же кадрам; узел мимики есть и в сцене Man_Rig; «Открыть в Blender» — с мимикой.
- **GEM-X, несколько людей**: свой персонаж Man_Rig у каждого участника (раньше всем доставался первый);
  видео 30 FPS не перекодируется при смене FPS/перемещения — кэш лица и распознавания сохраняется;
  нет проверки качества — старый отчёт не показывается; мимика без данных камеры — с предупреждением.
- **Надёжность и ошибки**: результат без видео импортируется при любой выбранной модели; повреждённый
  архив — понятная ошибка без мусорной папки; ffmpeg/ffprobe — короткая причина вместо командной строки,
  прерванное перекодирование не принимается за готовое; неверные настройки GEM-X — сразу при запуске;
  сбой сохранения прошлой версии не прерывает обработку; любая непредвиденная ошибка сервера доходит до
  окна текстом; очередь — в UTF-8 (английская Windows); `take.json` — повтор при блокировке файла на
  Windows, переименование во время обработки запрещено; частые ошибки переведены в английском интерфейсе.
- **Мелочи интерфейса**: скачивание прошлых версий в браузере; «Сцена Maya» учитывает выбранную модель
  (Man_Rig только при встроенном персонаже).
- **По тесту на Windows (12.10)**:
  - GEM-X падал по памяти на 4K-видео с телефона: видео для распознавания уменьшается (по умолчанию 1920 px), кадры
    читаются по одному, длинные треки — частями с плавной склейкой («Обработка частями»: авто/выкл/15–60 с);
    во время обработки видна видеопамять и ОЗУ WSL; у дубля — пики; «Тест производительности» в «Модели и инструменты»
    с рекомендациями; огромный лог ошибок сокращён;
  - Warp на драйвере CUDA 12.6: установщик ставит Warp 1.18.0+cu12, подсказка про драйвер 580+;
  - GVHMR, 4 человека: участники ставятся в общую сцену через камеру (раньше — в одну точку); при экспорте 60 FPS
    участники больше не «пропадают» на середине видео;
  - частота: экспорт как у видео; GEM-X можно распознавать на 30 или как у видео (до 60).
- **Лёгкая установка без ошибок**:
  - в «Модели и инструменты» — мастер «Установка шаг за шагом»: «Проверить компьютер» (версия Windows/macOS,
    память, место на дисках, папка дублей в OneDrive, длинные пути, драйвер NVIDIA и видеопамять, RTX 50,
    WSL: включён ли, WSL2, Ubuntu, виртуализация в BIOS, память WSL; доступ к серверам загрузки, прокси и
    проверка HTTPS антивирусом; Command Line Tools на Mac) — у каждой проблемы кнопка или точная команда;
    «Установить всё рекомендуемое» ставит только недостающее по результату проверки, после WSL просит
    перезагрузку и продолжает с того же места; первый запуск без моделей открывает мастер сам;
  - «Как исправить» под ошибкой установки и обработки — по базе известных ошибок (WSL 0x80370102/0x8007019e,
    нехватка памяти/диска, SSL, лимиты загрузок, антивирус, длинные пути, драйвер, RTX 50, SMPL-X и др.);
  - память WSL для GEM-X — одной кнопкой (с резервной копией .wslconfig и подтверждением);
  - «Отчёт для поддержки» в «Загрузки»: проверка компьютера, версии, журналы установки (без видео и анимаций);
  - журналы установки сохраняются; `mocapgate.py preflight` — та же проверка из командной строки;
  - quickstart: CHECK-COMPUTER.cmd, INSTALL.cmd не запустится из ZIP/Temp, журнал установки, понятные
    коды выхода и сообщения; установщик ставит WebView2 сам и говорит по-русски;
  - инструкции: docs/install.md (+ .en) и docs/troubleshooting.ru.md (+ .en) — симптом → причина → что сделать.
- **Новые возможности для анимации**:
  - **сглаживание дрожания** тела и пальцев (0…1, адаптивный фильтр без запаздывания) — для GVHMR и GEM-X;
  - **фиксация стоп для GEM-X**: опоры находятся сами, стопа прибивается к месту, ноги решаются IK (раньше
    было только у GVHMR); в ходе обработки видно скольжение «до → после»;
  - **экспорт для движков** (нужен Blender): Unreal — FBX со скелетом UE5 Manny (pelvis, thigh_l…) и костью
    root, Unity — FBX под Humanoid, glTF/GLB для веба и Godot; root motion по галочке; мимика — blend shapes;
    **все участники одним файлом**; **Live Link Face CSV** для мимики в Unreal / MetaHuman;
  - **свой персонаж**: загрузите .fbx/.glb/.blend со скелетом — кости сопоставляются сами (Mixamo, UE, Unity,
    Rigify, Character Creator, Daz, VRoid, Biped), A-/T-поза выравнивается, движение запекается на персонажа,
    мимика — на shape keys ARKit; результат FBX; персонажи хранятся для всех дублей;
  - **фрагменты для игр**: «Бесшовный цикл» (шов сглаживается, разворот выравнивается) и «Корневая кость
    (root motion)»;
  - **исправление кадров**: выделите участок In–Out и нажмите «Исправить эти кадры» — сбойные кадры
    заменяются плавной интерполяцией, прежняя версия остаётся в истории;
  - **проверка новой версии**: кнопка в шапке, если на GitHub вышла новая версия (анонимный запрос раз в 6 ч,
    отключается в «Настройках»).
  Проверено на Mac: модули, экспорт и перенос на персонажа через Blender 3.5, 4.2 и 5.2 (переимпорт и сверка
  костей, кадров, blend shapes), сквозной экспорт Unreal из интерфейса. Не проверено в самих Unreal/Unity и на
  настоящих моделях Character Creator / Daz / VRoid.
- **Установка без сбоев (по аудиту установки)**:
  - загрузки (Blender, ffmpeg, веса GVHMR, SOMA, YOLOX, модели MediaPipe) — во временный файл, докачка с места
    обрыва, 3 повтора, проверка размера/SHA; HTML-страница вместо модели отбрасывается; повторная установка
    продолжает скачивание, а не падает на недокачанном файле;
  - повреждённое или недосозданное окружение Python пересоздаётся; прерванный git clone — клонируется заново;
    uv берёт встроенный Python 3.12, а не качает его с GitHub;
  - WSL: выбирается только Ubuntu/Debian (не docker-desktop); «Installing» распознаётся и на русской Windows;
    зависший WSL — понятное сообщение; apt ждёт блокировку dpkg до 10 минут;
  - перед загрузкой: NVIDIA для GEM-X на Windows, свободное место (GEM-X 30 ГБ, GVHMR 15 ГБ), RTX 50-серия
    для GVHMR — сразу понятный отказ, а не после 10 ГБ;
  - причина сбоя установки — конкретная («apt-get install: код 100 — …»), без командных строк и пустых
    сообщений; отмена установки на Windows останавливает и процессы внутри WSL;
  - модели MediaPipe открываются и из папок с русскими буквами в имени пользователя;
  - SMPL-X можно загрузить архивом с сайта (.zip), инструменты SMPL-X (~1 ГБ) — только после подтверждения;
  - статус моделей не мигает «не установлено» на холодном WSL (запоминается последний удачный ответ);
  - журнал установки без тысяч строк прогресса; Mac без Command Line Tools — подсказка `xcode-select --install`.
- **Удобство (по аудиту интерфейса)**:
  - дубль с ошибкой или ещё не обработанный: настройки и кнопка «Сделать анимацию» видны всегда; при ошибке
    «модель не установлена» — кнопка «Открыть „Модели и инструменты“»; пустые плеер, 3D, обрезка и сравнение
    скрыты до появления анимации;
  - пометка «Настройки изменены — обработайте заново» только когда форма отличается от применённых настроек;
    правки в форме не теряются при смене участника/языка; несохранённые «Настройки» не затираются, кнопка
    «Сохранить» всегда на виду;
  - запись с камеры: выбор модели (без тихой подмены на другую), неустановленная — с подсказкой;
  - карточки моделей помечены «Не установлено», подсказка ведёт в раздел установки;
  - очередь запускается сама при добавлении дублей; дубль в очереди показывает это и кнопку запуска;
  - несколько видео в один дубль — включается «отдельный дубль на каждое видео»; файл можно убрать из списка;
  - тетрадка Colab скачивается прямо с панели ожидания результата;
  - статус «готов» больше не красный при низкой оценке; оценка — рядом со статусом; Colab без красной точки;
  - вкладки «Модели и инструменты» и «Настройки» не уезжают вместе с шапкой; новый дубль открывается сверху;
  - колесо над 3D прокручивает страницу (масштаб — после щелчка по виду или Ctrl/⌘ + колесо);
  - клавиши плеера: пробел, ←/→, I/O; переводы и склонения («1 кадр / 5 кадров»), подписи для экранного
    диктора; на Mac нет недоступной кнопки установки GVHMR; лишние кнопки скрыты.
- **GVHMR: кисти и лицо** проверены на двух людях: пальцы в BVH, мимика — CSV и Maya.
- **Отмена и удаление во время работы модели в WSL**: кроме `wsl.exe` останавливаются процессы GVHMR /
  GEM-X внутри Linux, запущенные с путями этого дубля (`pkill -KILL -f` в дистрибутивах GVHMR и GEM-X) —
  GPU и файлы дубля освобождаются.
- **GVHMR**: минимальная длительность участника; повторное распознавание теперь при смене любой настройки
  распознавания (раньше — только числа людей: «камера неподвижна» и фокус молча не применялись).

Проверено на macOS: нативный пакет ARM64 со встроенным CPython 3.12.13 (test_native_package: запуск без
системного Python, обработка, ошибки, отмена, 145 unit-тестов на скомпилированных модулях, Maya, FBX); конвейер GEM-X на подставном результате двух людей;
сборка сцены на тензорах (torch); удаление и корзина кнопками в Studio; шаги на реальной обработке;
экспорт мимики (CSV, Maya, FBX через Blender 3.5) для GVHMR и GEM-X на подставных данных; интерфейс в браузере
(ошибочный дубль, клавиши, пометка изменённых настроек, вкладки); 186 unit-тестов, установка — на заглушках.
**Не проверено**: настоящий GEM-X на NVIDIA/WSL с несколькими людьми и мимикой; остановка процессов
внутри WSL при отмене/удалении (на Mac проверена только логика команд). Это — цель тестирования на Windows.

## Сборка на Windows

В клоне `mocapgate-native-build` с ветки `codex/windows-release-0.3.3-beta.6`, PowerShell:

```powershell
uv python install 3.12.13
uv venv --python 3.12.13 .venv-native
uv pip install --python .venv-native\Scripts\python.exe -r requirements-native.txt
.venv-native\Scripts\python.exe -m unittest discover tests
.venv-native\Scripts\python.exe scripts\native_packaging.py build --out dist\native-0.3.3-beta.6
.venv-native\Scripts\python.exe tests\test_native_package.py dist\native-0.3.3-beta.6 --require-blender
.venv-native\Scripts\python.exe scripts\native_packaging.py zip dist\native-0.3.3-beta.6 --out dist\MoCapGate-0.3.3-beta.6-windows-x64-native.zip
$env:MOCAPGATE_NATIVE_PACKAGE = (Resolve-Path dist\native-0.3.3-beta.6).Path
cd apps\studio\desktop; npm ci; npx tauri build; cd ..\..\..
.venv-native\Scripts\python.exe scripts\make_windows_quickstart.py `
  --portable dist\MoCapGate-0.3.3-beta.6-windows-x64-native.zip `
  --installer (Get-ChildItem apps\studio\desktop\src-tauri\target\release\bundle\nsis\*.exe).FullName --out dist
```

## Что проверить на Windows

1. GEM-X на `Demo - Sports2D, two people` (или своём видео с двумя людьми), «Сколько людей» = 2:
   два участника, у каждого скелет на видео, балл проверки, BVH/Maya; прыгун стоит на возвышении,
   у дубля — высота камеры над полом.
2. Во время обработки — список шагов и проценты; при сбое — понятная причина.
3. Удалить дубль — папка исчезает из `Documents\MoCapGate Takes`; «Удалить старую корзину».
4. Отменить/удалить дубль посреди GEM-X и посреди GVHMR: в `wsl -d <дистрибутив> ps aux` не должно остаться
   python-процессов с путём дубля; `nvidia-smi` — память GPU освобождается.
5. GEM-X и GVHMR с «Полное лицо и мимика»: у каждого участника кнопка «Мимика (52 кривые, CSV)»; в Maya у
   сцены есть узел `FaceExpressions` с анимированными атрибутами (jawOpen, eyeBlinkLeft…); FBX в Unreal/Unity —
   меш FaceExpressions с анимированными blend shapes. Проверить с Blender 4.x, если он установлен.
6. Английский интерфейс: ошибка (например, повреждённое видео) — по-английски.
7. Установка с нуля на чистой Windows: GEM-X и GVHMR в WSL; оборвать интернет посреди загрузки и нажать
   «Установить» снова — загрузка продолжается; отменить установку — в `wsl -d Ubuntu ps aux` нет setup_*.py.
8. Экспорт для движков: Unreal FBX → импорт в UE5 на скелет Manny (с root motion и без), Unity FBX → Humanoid,
   GLB — открыть в любом просмотрщике; «Свой персонаж» на модели Mixamo — анимация на персонаже в FBX.
9. Фрагмент с «Бесшовный цикл» + «Корневая кость» — в движке цикл без рывка на шве.
10. Чистая Windows: CHECK-COMPUTER.cmd → затем INSTALL.cmd; в Studio «Проверить компьютер» → «Установить всё
    рекомендуемое» → перезагрузка после WSL → снова кнопка → GEM-X. Журнал: %LOCALAPPDATA%\MoCapGate Studio\logs.
11. GEM-X на 4K-видео с телефона (4 человека): «Авто» частями, 1920 px — без «процесс остановлен системой»; под полосой
    видеопамять/ОЗУ; «Тест производительности» → «Применить для новых дублей». Переустановить GEM-X — в журнале «Warp CUDA: True».
12. GVHMR с 4 людьми, видео 60 FPS: участники стоят на своих местах в 3D и видны до конца видео.
